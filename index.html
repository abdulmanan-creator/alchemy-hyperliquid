Everything you need

From a single line of code to advanced execution.

Six primitives cover most of what a trading agent or bot will need. The full SDK surfaces the rest.

One-Line Trading

Market buy or sell by ticker. No order builder, no signing dance — the SDK handles it end-to-end.

sdk.marketBuy("BTC", { notional: 100 })

Zero Custody

Private keys are signed locally and never transit our servers. We see signed payloads, not secrets.

// Private key stays local

Real-Time Streaming

WebSocket subscriptions for trades, book updates, fills, and account state — auto-reconnect included.

sdk.stream.trades(["BTC"], cb)

Full Market Data

L2 books, candles, funding history, mark and oracle prices. Block-perfect, delivered by Alchemy.

sdk.info.l2Book("ETH")

HIP-3 Markets

Permissionless market dexes from any builder. Address them as dex:SYMBOL and trade the same way.

sdk.buy("xyz:SILVER", { notional: 11 })

Advanced Orders

TWAP, scale, post-only, reduce-only, IOC, ALO, and trigger orders — all behind ergonomic primitives.

sdk.twapOrder("BTC", { size: 0.1 })

Exchange — Build (no signature)

6 endpoints · no auth
POST/exchangeBuild OrderTRY IT

Construct a typed-data order payload ready to be signed in the user's wallet. No signature is performed server-side — the response is the exact EIP-712 message you'll sign before calling Send Order.

FieldTypeDescription
action.orders[].assetnumberAsset id, e.g. 0 for BTC perp. Use info.meta to resolve.
action.orders[].side"buy" | "sell"Order side.
action.orders[].pricestringLimit price as a decimal string. Optional for IOC.
action.orders[].sizestringOrder size in base units.
action.orders[].tif"Alo" | "Gtc" | "Ioc"Time-in-force. ALO is post-only.
vaultAddressstring opt.Trade on behalf of a vault.
Returns{ typedData: EIP712, nonce: number, builderFee: { rate, max } }
POST https://api.alchemy.com/hyperliquid/exchange
curl -X POST https://api.alchemy.com/hyperliquid/exchange \
  -H "Content-Type: application/json" \
  -d '{
    "type": "build",
    "action": {
      "type": "order",
      "orders": [{ "asset": 0, "side": "buy", "price": "62500", "size": "0.001", "tif": "Gtc" }]
    },
    "wallet": "0xAbC…"
  }'

Build a market order with intelligent slippage protection. Submit a target notional or size and the endpoint computes a marketable limit price from the current book, attaching the builder fee.

FieldTypeDescription
action.orders[].assetnumberAsset id to trade.
action.orders[].side"buy" | "sell"Direction of the trade.
action.orders[].notionalstring opt.USD notional to fill. Mutually exclusive with size.
action.orders[].sizestring opt.Size in base units.
slippageBpsnumber opt.Max acceptable slippage in basis points. Default 50.
Returns{ typedData, nonce, limitPrice, estimatedFill }
POST https://api.alchemy.com/hyperliquid/exchange

POST/exchangeBuild Approval (approveBuilderFee)TRY IT

Build the one-time EIP-712 payload that authorises Alchemy as a builder for the connected wallet. The user signs it once to set their maxFeeRate ceiling — every subsequent order's builder fee falls inside that ceiling.

FieldTypeDescription
action.builderaddressAlchemy's builder address (auto-filled).
action.maxFeeRatestringCeiling as a percent, e.g. "1%". The actual fee on each order will be lower.
walletaddressThe user wallet granting the approval.
Returns{ typedData: EIP712, nonce, expiresAt }
POST https://api.alchemy.com/hyperliquid/exchange
curl -X POST https://api.alchemy.com/hyperliquid/exchange \
  -d '{ "type":"buildApproval", "action": { "maxFeeRate":"1%" }, "wallet":"0xAbC…" }'

FAQ

Questions, answered.

A zero-custody REST builder API for trading on Hyperliquid. You sign locally with your private key; Alchemy routes the signed payload to the chain and earns a small builder fee in return. Same product surface as Hyperliquid's own API, with extras like preflight, pre-built cancels, and language SDKs.
First, you call a build* endpoint to get an EIP-712 typed-data payload. Then you sign it locally — either in a hardware wallet, browser wallet, or with a local key the SDK manages. Finally you call the matching send* endpoint with the signature. Alchemy verifies the signature, attaches the builder fee within your approved ceiling, and forwards to Hyperliquid.
No. Never. Alchemy sees signed payloads and routes them — your keys never leave your machine and we have no way to move funds without a signature you produce.
Two layers. Alchemy charges a builder fee — 0.04% on perpetuals, 0.05% on spot — within a ceiling you approve once. Hyperliquid itself charges the exchange fee: 0.045% taker / 0.015% maker on perps, 0.070% taker / 0.040% maker on spot. There are no monthly platform fees.
Hyperliquid lets any registered "builder" attach a small fee to orders they route to the matcher, capped by a user-signed approval. Alchemy is a builder. The protocol enforces a maximum of 0.1% on perps and 1% on spot; the user signs a ceiling at or below that, and Alchemy charges below the ceiling on every order.
Visit /approve, connect your wallet, and sign a single EIP-712 message setting your maxFeeRate. Revoking is symmetric — return to the same page and click "Revoke" to publish a revocation payload to the protocol. Either action takes one signature.
Every perp and spot pair on Hyperliquid mainnet, plus markets on any HIP-3 dex and assets staged for HIP-4 launches. The SDK addresses HIP-3 markets with a dex:SYMBOL namespace so the call signature stays the same: sdk.buy("xyz:SILVER", { notional: 11 }).
No. The SDK signs locally — either with a hot key you supply (kept in memory), an injected browser wallet, or a hardware signer. Alchemy receives signed payloads, never raw keys.
